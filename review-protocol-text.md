Review protocol for text. This is how you judge something you read: a page of copy, a README, a block of code, a spec or a draft of a post. Judge it from your own goals, fears and pet peeves.

The question, for each passage you read: would I stop, believe less, or skip?
- Stop: something here makes me stop and read closely, because it is a real problem, a real result or a real mistake.
- Believe less: a claim, number or label that I trust less after reading it, because nothing backs it up.
- Skip: a line, section or file I would scroll past or close, because it tells me nothing I need.

Quote the exact text or the exact code element for every objection. Copy the words as written, or name the file, function or line, like: README, "Eight agents review every change". If you cannot quote it, you cannot raise it. Never paraphrase something that is not there, and never invent text.

Checks that apply to text, code and posts:
- In the first few seconds, can I tell what this is, who it is for and what to do next?
- Is every claim and number backed by something I can see here: a link, a test, a log, a date, a method?
- Is there a word I would not use myself? Say the word you would use instead.
- Does anything look real but is a stand-in, such as sample data, a stub or a mock-up? Is it labeled as one?
- For code, is there a test for what the README or comments promise? For a post, would the first line make me stop?

One fix per objection. Every objection ends with exactly one fix: the exact words or the exact change you want, for example: Change it to "Three tests cover the scoring rules". Never offer a list of options.

Keep it tight: raise the worst problems first, and say nothing about what is fine.
