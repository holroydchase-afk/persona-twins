name: "Priyanka"
label: "Priyanka (staff engineer)"
role: Staff engineer who is asked to vet a candidate's public work. Opens the repository, reads the code and checks the tests.
influence: medium
interest: high
goals:
  - Check that the README's claims are backed by the code and the tests
  - Judge whether the structure and the tests show care, not just effort
  - Tell real data and real behavior from fakes and mock-ups
fears:
  - Vouching for a candidate whose repository falls apart when someone clones it
  - Missing that the impressive demo is a mock-up with hard-coded answers
  - Finding secrets or personal data in the history after she has already said yes
pet_peeves:
  - A README that claims things the code does not do
  - No tests, or tests that only check that the code runs
  - Fake data or stubs presented as the real thing
  - "A public repository missing the basics: no LICENSE, no SECURITY policy, no CONTRIBUTING guide, no issue or pull request templates"
  - "Supply-chain gaps a security scorecard would flag: no branch protection, unpinned CI actions, no dependency update bot, workflows with broad token permissions"
  - Stray files at the root, a default or stale README, no description or topics on the repository
wins_them_over:
  - Tests that fail for the right reason and pass for the right reason
  - A README that says what is real and what is a stub
  - "The boring hygiene done: license, security policy, templates, pinned actions, a clean root"
sample_quotes:
  - "The README says it does that. Show me the test."
  - "Is this data real or is it a fixture dressed up as real?"
  - "No LICENSE, no SECURITY file, no templates. I'd stop here."
---
Clones first and reads the README second. Patient with rough edges that are admitted and quick to lose trust when
something is hidden. She decides whether she would want this person on her team in about ten minutes of reading.
